# League of Gangstars

The complete history of an ESPN fantasy football league, running since 2010, at
**https://leagueofgangstars.com**. Trophy room, all-time records, owner profiles, rivalries,
draft tendencies and a few hundred fun facts, all generated from ESPN data that re-syncs
every week.

```
ESPN  ──(weekly GitHub Action)──▶  data/*.json + public/logos  ──(git push)──▶  Vercel builds the Next.js site
```

No database, no server: the Python job is the only thing that talks to ESPN, it commits JSON,
and the site is statically generated from that JSON.

## Repository layout

| Path | What it is |
|---|---|
| `app/`, `components/`, `lib/` | Next.js 16 site (TypeScript, Tailwind, Framer Motion, Recharts) |
| `data/raw/{year}.json` | One snapshot per season straight from ESPN |
| `data/league.json` | Normalized seasons keyed by owner (teams, matchups, drafts, box scores) |
| `data/records.json` | Everything derived: trophies, records, careers, H2H, rankings, facts |
| `data/owners.json`, `data/coverage.json`, `data/meta.json` | Owner directory, per-season data coverage, sync metadata |
| `public/logos/{year}/` | Team logos downloaded from ESPN |
| `public/audio/theme.mp3` | Theme music (see below) |
| `sync/espn_sync.py` | Pulls seasons from ESPN |
| `sync/normalize.py` | Applies `owners.yml` + `overrides/`, writes `league.json` and the coverage report |
| `sync/build_stats.py`, `sync/stats/` | Computes `records.json` |
| `sync/owners.yml` | **Owner identity map** (edit this) |
| `sync/overrides/{year}.yml` | Manual data for seasons ESPN can't fully provide (edit these) |
| `.github/workflows/sync.yml` | Weekly sync |

## First-time setup

### 1. ESPN secrets

The league is private, so the sync needs your ESPN cookies. In the GitHub repo go to
**Settings → Secrets and variables → Actions** and add:

| Secret | Where to find it |
|---|---|
| `ESPN_LEAGUE_ID` | The number after `leagueId=` in any ESPN league URL |
| `ESPN_S2` | Log in at fantasy.espn.com in Chrome → DevTools → Application → Cookies → `https://fantasy.espn.com` → value of `espn_s2` |
| `ESPN_SWID` | Same place, value of `SWID`, **including the curly braces** |

Optionally add a repository **variable** `FIRST_SEASON` (defaults to 2010).

`espn_s2` expires after roughly a year. When it does, the workflow fails with instructions in
the job summary; paste in fresh cookies and re-run.

### 2. First sync

Actions → **Sync ESPN data** → **Run workflow** → tick **full_refresh**. The first run fetches
every season, downloads logos, generates `sync/owners.yml` stubs for every ESPN account it saw,
and commits `data/`. Read the job summary: it prints the owner map and a coverage matrix.

### 3. Map teams to owners (`sync/owners.yml`)

Every stat on the site is keyed by owner, never by team name. ESPN identifies people by an
account id (`swid`), so renamed teams already stick to the right person. You only need to edit
the file to:

- **Rename** an owner: change `name` (that is what the site shows, e.g. `Johnny`).
- **Merge** two ESPN accounts that are the same person: put both swids under one owner and
  delete the other entry.
- **Pin** a team-season that ESPN has no owner for (very old seasons):
  ```yaml
  - key: johnny
    name: Johnny
    swids: ["{ABC-123}"]
    teams:
      - { year: 2010, teamId: 4 }
  ```
- Set a `color` (hex) used for the monogram badge when a season has no logo.

`key` is the URL slug (`/owners/johnny`); keep it stable. Entries marked `auto: true` were
generated by the sync; remove the flag once you have reviewed them. After editing, re-run the
workflow with **full_refresh** (or run the pipeline locally) so history is re-keyed.

### 4. Fill gaps for old seasons (`sync/overrides/`)

ESPN's history endpoint is patchy for older seasons. `data/coverage.json` and the job summary
say exactly what is missing per season ("2011: final standings screenshot"). For each such
season the sync writes a pre-filled template to `sync/overrides/templates/{year}.yml`. Copy it
to `sync/overrides/{year}.yml`, fill in what you can from screenshots, commit, and re-run.
Overrides always win over ESPN data. Supported keys (all optional):

```yaml
season: 2011
champion: johnny
runner_up: mike
third: kevin
last_place: danny
final_standings: [johnny, mike, kevin, ...]     # owner keys, first to last
teams:                                         # season line when ESPN lacks it
  - { owner: johnny, team_name: "Vick in a Box", wins: 10, losses: 3, ties: 0, points_for: 1543.2, points_against: 1388.9, playoff_seed: 1 }
matchups:                                      # optional week-by-week scores
  - { week: 14, home: johnny, away: mike, home_score: 112.4, away_score: 98.1, playoff: true }
champion_roster:                               # shown in the Trophy Case
  - { player: "Aaron Rodgers", position: QB, nfl_team: GB, slot: QB, points: 31.2 }
```

Stats degrade gracefully: a season with only a champion still counts toward titles and
finishes; one with team records also counts toward career and season records; single-game
and streak records only use seasons with weekly scores.

### Optional: hand adjustments (`sync/adjustments.yml`)

Some things are the commissioner's call. `sync/adjustments.yml` is applied on top of the computed
stats every sync:

```yaml
goat_overrides: { john-meier: 91.2 }         # replace an all-time-ranking score (row is marked "adjusted")
hide_facts_for: [jp-woodward]                # no fun facts about these owners, by key or by name
custom_facts:                                # hand-written facts shown with the generated ones
  - { id: johnny-dance, category: trophies, ownerKey: john-meier, href: /owners/john-meier,
      text: "Johnny wins the championship 66% of the time he makes the playoffs." }
```

Single-game records (highest score, blowouts, closest games, title-game marks) only consider
seasons from `RECORD_MIN_YEAR` in `sync/config.py` (2019) so eras with different scoring don't
mix. Season, career and streak records use full history.

### 5. Deploy on Vercel + domain

1. vercel.com → **Add New Project** → import this GitHub repo. Framework is detected as Next.js;
   no environment variables are needed.
2. **Settings → Domains** → add `leagueofgangstars.com` and `www.leagueofgangstars.com`
   (redirect www → apex).
3. At your registrar, point DNS at Vercel:
   - `A` record, host `@`, value `76.76.21.21`
   - `CNAME` record, host `www`, value `cname.vercel-dns.com`
   Vercel issues HTTPS automatically once DNS propagates.
4. Every push to `main` (including the weekly data commit) redeploys. `vercel.json` skips builds
   for commits that only touch the sync code or docs.

## Weekly sync

The workflow only appears in the Actions tab once `.github/workflows/sync.yml` is on the
default branch (`main`).

`.github/workflows/sync.yml` runs Tuesdays at 08:00 ET (after Monday Night Football is final),
refreshes the current season, recomputes everything, runs the tests, and commits. Run it by hand
any time from the Actions tab.

## Running locally

```bash
# data pipeline
pip install -r sync/requirements.txt
export ESPN_LEAGUE_ID=... ESPN_S2=... ESPN_SWID='{...}'
cd sync
python espn_sync.py --all        # or: python generate_sample.py  (fake league for development)
python normalize.py --report
python build_stats.py
python -m pytest -q tests
cd ..

# site
npm install
npm run dev                      # http://localhost:3000
npm run lint && npm run build
```

Without ESPN credentials, `python sync/generate_sample.py` builds a synthetic league so the
site can be developed and previewed; the site shows a "sample data" banner until a real sync
replaces it.

## Theme music

The site plays `public/audio/theme.mp3` on load with a visible mute button (top right on
desktop, floating bottom-right on mobile). Browsers block audio until the visitor interacts, so
a "Tap for sound" pill appears until their first click. The preference persists per browser.

The bundled track is "Heroic Age" by Kevin MacLeod (incompetech.com), licensed under
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); the attribution in the footer is
required if you keep it. To use something else, replace `public/audio/theme.mp3` with any track
you have the rights to and update the footer credit in `components/Footer.tsx`. Actual NFL Films
scores are copyrighted and cannot be shipped.

## Data notes

- Trades come from ESPN's league activity feed, which only exists from 2019 onward. Each side of
  a trade is scored by what the players it received went on to produce for their new owner that
  season, which is what "most lopsided" ranks. Run the workflow with **full refresh** once after
  updating to load historical trades.

- Owner pages show "Your MVP" with a headshot. Headshots are downloaded once per player from
  ESPN's public CDN during the sync (`sync/headshots.py`) into `public/headshots/` and served
  statically; if a download fails the page shows a monogram badge instead.

- Player-level weekly box scores exist from 2019 on; earlier seasons have team scores, standings,
  drafts and end-of-season rosters only.
- Championship rosters use the title-game lineup (2019+), otherwise the end-of-season roster,
  otherwise `champion_roster` from an override.
- Team logos are downloaded once per season and re-downloaded only if ESPN's URL changes.
